# Receipt Lens — OCR Expense Tracker

Flutter/Dart mini-project for scanning paper receipts, extracting key fields entirely on-device, reviewing the result, then tracking local spending.

## Implemented features

- **Live receipt camera:** rear-camera preview, tap-to-focus, flash toggle and a receipt framing overlay.
- **Image crop:** user crops the captured receipt before OCR.
- **Offline OCR:** `google_mlkit_text_recognition` runs Google ML Kit on-device. No receipt image or extracted text is sent to a server.
- **Receipt parser:** heuristic regex extracts Vietnamese/English total labels (for example `Tổng cộng`, `Total`, `150.000 đ`), `DD/MM/YYYY` dates, a likely merchant name, and a suggested category.
- **Mandatory review step:** merchant, amount, date, and category are all editable before the user confirms saving. Raw OCR text is available for inspection.
- **Local-first persistence:** `sqflite` stores expenses; receipt images are copied into the app documents directory as a local cache.
- **Insights without chart packages:** animated category donut and seven-day bar chart are drawn with `CustomPainter`.
- **Transaction history:** receipt thumbnails, category/date/amount details, swipe-to-delete, and light/dark system themes.

## Architecture

```text
lib/
├── core/                 # Theme and display helpers
├── models/               # Expense, receipt draft, category enum
├── services/             # ML Kit OCR/parser, SQLite, local image cache
├── providers/            # ChangeNotifier state and derived chart datasets
├── screens/              # Dashboard, camera, OCR review, history
└── widgets/              # CustomPainter charts and reusable expense row
```

```text
Camera → Crop image → ML Kit OCR + regex heuristics → Review/edit
       → copy image locally + SQLite → Provider notifies → custom charts redraw
```

`ExpenseProvider` is the only UI state owner. Screens never query SQLite directly; they send an action to the provider, which calls `DatabaseService` and notifies the dashboard/history UI.

## Run locally

This workspace contains application source. It was prepared without a Flutter SDK installed, so generate the native runner files once on a machine with Flutter 3.x/Dart 3 installed:

```bash
flutter create --platforms=android,ios .
flutter pub get
flutter run
```

The app must run on a physical Android/iOS device because it uses the camera. After `flutter create`, add the following platform permissions (the runner generator may replace platform files).

**`android/app/src/main/AndroidManifest.xml`** — immediately under `<manifest>`:

```xml
<uses-permission android:name="android.permission.CAMERA" />
```

**`ios/Runner/Info.plist`** — inside the root `<dict>`:

```xml
<key>NSCameraUsageDescription</key>
<string>Receipt Lens uses the camera to scan a receipt.</string>
```

For Android, use `minSdkVersion 21` or newer. ML Kit documentation and the chosen Flutter plugin versions may require a higher Android compile SDK; use the version generated by your current Flutter stable channel.

Build a release APK after testing:

```bash
flutter build apk --release
```

The output is `build/app/outputs/flutter-apk/app-release.apk`.

## Parser notes and limitations

The parser intentionally chooses the largest amount next to a total-like label, falling back to the largest VND-formatted amount. This works well for common Vietnamese receipts, but OCR and receipt layouts vary. The review screen is therefore a core correctness feature, not an optional screen. The app keeps data only on the device and has no sync or cloud backup.

## Suggested 2–3 minute demo

1. Open the dashboard and explain the offline/local-first design.
2. Capture a real receipt, toggle flash or tap to focus, then crop it.
3. Show OCR extraction and manually amend a field in the review screen.
4. Save and show the transaction list plus animated donut/bar charts updating.
